# Mesa report draft: a lavapipe draw of the second derivative of a square root crashes the GPU process

**A draft. It is not filed; Alexander approves it before anything is sent upstream.** It backs `GLSLTiers.LAVAPIPE_CRASH` in
`test/glsl_tiers.js` (issue #1815, tracked for lifting in the issue the PR names).

## Report text

**llvmpipe (Vulkan): a fragment shader with the second derivative of a square root crashes the process (SIGSEGV) at its first draw.**

Environment: Mesa 25 (lavapipe), LLVM 20.1.2, x86-64 with AVX-512 (Intel Xeon, 4 cores), headless Chrome over ANGLE's Vulkan
back end (`--use-angle=vulkan`). Not checked: Mesa 26 / LLVM 21, other CPUs.

What happens: a WebGL2 draw of `fragment.glsl` (with `vertex.glsl`) takes 730 ms in `readPixels`, which returns all zeros, and the
GPU process then exits with SIGSEGV (`exit_code=11`, 2 ms after `readPixels` returns). `linkProgram` returned after 3 ms (the
link is lazy) and `drawArrays` was issued at once, so the time is the pipeline being built; `getError()` says 0 and
`isContextLost()` false at that moment. Expected: the pixels, no crash.

The draw:
- a 402 × 43 `RGBA32F` render target, one full-screen triangle (`vertex.glsl`, 3 vertices), viewport 402 × 43;
- `uPts`: a 402 × 1 `RGBA32F` texture on unit 0 (points of the complex plane, `(re, im, re, im)`), `uModes`: a 2 × 43 `RGBA32F`
  texture on unit 1 (one row per output row; a row selects what to compute: `(0, a, b)` is a range of the chain);
- `uNoUnroll` = 0, `uSheetW` = 2;
- `uChain` (`vec4[5]`, the 20 floats in order): `[3.1415927410125732, 0, 1, 0, 1, 0, -0.6931471824645996, 0, 0.0010000000474974513, 0, 3.1415927410125732, 0, 1, 0, 2, 0, 2, 3.1415927410125732, 0, 0]`.
The fragment shader is generated by the application for the chain `\sqrt{z}`, then d/dz, then d/dz. It has loops of 8 and no
local array and no dynamically indexed array. The harness that draws it is `test/glsl_test.js` (`runGPU`); in the repository
`node ci/glsl.js --only glsl --filter 'sheets sqrt d d'` on lavapipe reproduces the crash (with `LAVAPIPE_CRASH`'s entry
removed from `test/glsl_tiers.js`).

What changes it: the same program with one d/dz or with three does not crash; with two, the variants `root d d`, `z^{0.5} d d`
and `\sqrt{z+1} d d` crash and `\sqrt{z^2-1} d d` fails 6418 of 6442 values; `sin`, `log` and `exp` twice do not. It is
not memory (under 400 MB), not the stack (`ulimit -s` 8 MB, 64 MB, 1 GB), and not the AVX-512 miscompile of #1735
(`GALLIUM_OVERRIDE_CPU_CAPS=avx` and `avx2` crash the same).

## Missing before it is sendable
- A standalone reduction: one HTML or C file that needs none of the application (the shader reduced, the draw written out).
- A check on a current Mesa (26.x), and on another CPU.

## How these files were made
`fragment.glsl` is the source the page compiled for the chain (`window.__lastSrc` in a local build of the page, the program of
`compile()` in `test/glsl_test.js`); `vertex.glsl` is the page's `VS`; `uChain` is `gc.fill(u)` for the chain. They do not
follow later changes of the shader library.
